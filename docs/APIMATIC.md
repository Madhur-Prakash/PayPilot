## What gets built

[`apimatic/`](../apimatic) is an [APIMatic](https://docs.apimatic.io/v4/) project for **PayPilot's own API**. From it
the APIMatic CLI builds:

| Artefact | Contents |
| --- | --- |
| Developer portal | API reference with a live playground, cURL, Python and TypeScript samples, the guides in `src/content/`, SDK pages, a Context Plugin page, and AI page actions (`llms.txt`) |
| Python SDK | `pay_pilot_api`, synchronous and asynchronous clients, grouped by API tag |
| TypeScript SDK | The same operations for Node and the browser |
| Context Plugin | Grounded context for AI coding agents (manifests for Claude Code, Codex and Cursor), so an external supplier agent can integrate with PayPilot the way the PayPal Context Plugin helped build PayPilot's PayPal integration |

The four guides are: authentication, procure-to-pay, the supplier-agent protocol, and money controls.

## Project layout

```
apimatic/
  src/
    apimatic.json          portal branding and navigation, plugin identity, SDK languages
    spec/openapi.json      generated by scripts/export_openapi.py - do not edit
    content/
      index.md             portal home page
      guides/              authentication, procure-to-pay, supplier-agent protocol, money controls
```

Generated output is git-ignored and rebuilt by the script: `apimatic/portal/`, `apimatic/sdk/python`,
`apimatic/sdk/typescript`, `apimatic/plugin/`.

## Export the specification

```bash
python scripts/export_openapi.py      # writes docs/openapi.json and apimatic/src/spec/openapi.json
```

The spec is generated from the FastAPI app itself, so it always matches what the code serves (200 operations in
18 tag groups). It needs no database and contains no credentials. The exporter adapts FastAPI's output for
APIMatic:

* writes OpenAPI 3.0.3 (FastAPI's 3.1 `anyOf [X, null]` becomes `nullable`, so real `null`s are accepted);
* adds the server URLs, a description and the licence;
* gives every operation a readable operation id (`create_procurement`, `capture_payment`), which become SDK method
  names, and a description;
* strips Pydantic's per-field titles, inlines file-upload bodies, drops empty enum values and declares every tag.

The result passes `apimatic api validate` with 0 errors. [`docs/openapi.json`](openapi.json) also imports into
Postman and Swagger tooling.

## Build the portal, SDKs and plugin

Requirements: the APIMatic CLI 2.x (`npm i -g @apimatic/cli@2`, Node 22.14+) and an APIMatic account. Either sign in
once with `apimatic auth login`, or put an API key (APIMatic dashboard -> Account -> API Keys) in the root `.env` as
`APIMATIC_API_KEY`. The scripts pass it as `--auth-key` and never print it.

```bash
scripts/apimatic.sh             # refresh spec, validate, portal, Python and TypeScript SDKs, plugin
scripts/apimatic.sh serve       # live preview at http://localhost:23513
scripts/apimatic.sh portal      # only the static portal -> apimatic/portal
scripts/apimatic.sh sdk         # only the SDKs -> apimatic/sdk
scripts/apimatic.sh plugin      # only the Context Plugin -> apimatic/plugin
```

On Windows PowerShell: `.\scripts\apimatic.ps1` with the same steps. `apimatic plugin publish` prints the git
commands to publish the plugin; review them before running.

## Use the Python SDK

```bash
pip install ./apimatic/sdk/python      # or download python.zip from the portal's SDK page
```

```python
from pay_pilot_api import PayPilotApiClient

# environment="production" targets the hosted API; base_url points at any other server.
with PayPilotApiClient(base_url="http://localhost:8000") as anon:
    session = anon.auth_api.login({"email": "owner@juniperoak.com", "password": "Autopilot@2024"})
    token = session.data.tokens.access_token

with PayPilotApiClient(base_url="http://localhost:8000", http_bearer=token) as client:
    radar = client.paypal.subscription_radar(days_back=90, days_ahead=45)
    print(radar.data["summary"])
    procurements = client.supply_agents.list_procurement()
```

`AsyncPayPilotApiClient` exposes the same methods as coroutines. Methods are grouped like the API tags
(`client.supply_agents`, `client.paypal`, `client.inventory`, ...); the full list is in the generated
`api-reference.md`. The SDK was installed and run against the local API: login, the revenue radar and the
procurement list all deserialise into typed models.

## Host the portal

[`render.yaml`](../render.yaml) includes **`paypilot-docs`**, a free Render static site that runs
`apimatic portal generate` on every deploy and serves `apimatic/portal`. Set `APIMATIC_API_KEY` on that service when
Render asks; without it the build fails harmlessly and the API and web app are unaffected. `portal.site.url` in
[`apimatic/src/apimatic.json`](../apimatic/src/apimatic.json) is `https://paypilot-docs.onrender.com`; change it if
the service gets another name.
